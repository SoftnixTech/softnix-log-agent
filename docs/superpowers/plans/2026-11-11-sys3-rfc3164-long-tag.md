# SYS-3 Long RFC 3164 Tags Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking. Execute the tasks in order. The owner chose option A on 2026-11-11 (see R-0), so nothing blocks this plan.

**Goal:** `parse_rfc3164` accepts a `TAG[PID]` whose name and PID are each up to 128 characters, so long Windows provider names (for example the RDP `TerminalServices-*` providers) keep `application` and `process_id`. Everything accepted today parses identically.

**Architecture:** One condition changes in `parse_rfc3164` (`src/pipeline/syslog.rs:166`): the single `tag.len() <= 48` check, which counts the `[pid]` suffix, becomes two separate bounds on the name and the PID. The sender is untouched (option A).

**Tech Stack:** Rust 2021, no new dependency.

**Spec:** `docs/superpowers/specs/2026-11-11-sys3-rfc3164-long-tag.md`

**R-1: `Option::is_none_or`, not `map_or(true, …)`.** The spec's sketch uses `map_or(true, …)`, which current clippy rejects (`unnecessary_map_or`) under `-D warnings`. `is_none_or` has been stable since Rust 1.82, below the 1.98 MSRV.

**R-2: The PID is measured without its closing `]`**, exactly as it is stored (`trim_end_matches(']')`), so the bound applies to what ends up in `process_id`.

- [ ] **Step 2: the fix (green).** Insert directly **before** the `/// RFC3164: <PRI>Mmm dd hh:mm:ss HOSTNAME TAG[pid]: MSG` doc comment:

```rust
/// Longest RFC 3164 TAG name, and longest PID inside `TAG[PID]`, that
/// `parse_rfc3164` accepts. RFC 3164 says 32 for the whole TAG, but real
/// senders (the agent's own included) do not truncate: Windows provider names
/// reach 66 characters. The bound only keeps a long token before the first
/// `:` of a tag-less line from being taken as a tag without limit.
const MAX_TAG_NAME: usize = 128;
const MAX_TAG_PID: usize = 128;

```

  In `parse_rfc3164`, replace the whole `// TAG[pid]: message` block (from that comment through the closing `}` of `if let Some(colon) = remainder.find(':') {`) with:

```rust
    // TAG[pid]: message
    if let Some(colon) = remainder.find(':') {
        let (tag, msg) = remainder.split_at(colon);
        let (name, pid) = match tag.find('[') {
            Some(br) => (&tag[..br], Some(tag[br + 1..].trim_end_matches(']'))),
            None => (tag, None),
        };
        if !tag.contains(' ')
            && name.len() <= MAX_TAG_NAME
            && pid.is_none_or(|p| p.len() <= MAX_TAG_PID)
        {
            match pid {
                Some(pid) => {
                    ev.application = Some(name.to_string());
                    ev.process_id = Some(pid.to_string());
                }
                None if !tag.is_empty() => ev.application = Some(tag.to_string()),
                None => {}
            }
            ev.message = msg[1..].trim_start().to_string();
            return true;
        }
    }
```

  The two lines after the block (`ev.message = remainder.to_string();` and `true`) stay. `cargo test --lib pipeline::syslog` is all green.
